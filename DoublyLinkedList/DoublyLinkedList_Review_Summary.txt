[1] DLLOperations.c (Question 43)
    Category: Fundamental ADT Operations & Dual-Pointer Semantics
    Problem Statement:
      Design and implement a complete Doubly Linked List (DLL) Abstract Data Type
      supporting fundamental operations:
      1. insertAtBeginning: Insert node at head in O(1) time.
      2. insertAtEnd: Insert node at tail in O(N) time (or O(1) with tail pointer).
      3. deleteFromBeginning: Delete head node in O(1) time and free memory.
      4. deleteFromEnd: Delete tail node in O(N) time and free memory.
      5. display: Print elements from head to tail.
    Key Algorithmic Concepts:
      - Uses double pointers (struct Node** head) to mutate caller's head address.
      - Maintains bidirectional invariant: every internal node must satisfy
        node->next->prev == node and node->prev->next == node.
      - Ensures the head node's prev pointer is strictly grounded to NULL.
    Why It's Unique:
      Establishes the foundational node structure (prev, data, next) upon which
      all other DLL questions depend. Unlike Singly Linked Lists, every insertion
      and deletion requires coordinating both forward and backward pointer links.

[2] InsertAtPositionDLL.c (Question 44)
    Category: Positional 4-Way Pointer Splicing & Boundary Guarding
    Problem Statement:
      Insert a new node with value val at a specified 1-based index position pos.
      The routine must handle:
      - Insertion at the beginning (pos == 1).
      - Insertion between two existing nodes.
      - Insertion at the end of the list (pos == length + 1).
      - Reporting out-of-bounds positions (pos < 1 or pos > length + 1).
    Key Algorithmic Concepts:
      - Traverses to predecessor node at (pos - 1).
      - Executes a 4-pointer cross-wiring sequence.
      - Guard check: verifies (curr->next != NULL) before updating
        curr->next->prev to prevent segmentation faults when appending at tail.
    Why It's Unique:
      In an SLL, intermediate insertion updates only 2 pointers. In a DLL, it
      requires a 4-way pointer surgical splice. It is the definitive test of
      pointer manipulation order and boundary guarding in C.

--------------------------------------------------------------------------------

[3] DeleteAtPositionDLL.c (Question 45)
    Category: Positional Node Deletion & Dual-Neighbor Re-linking
    Problem Statement:
      Delete the node at a specified 1-based index position pos, free its memory,
      and return the deleted value. The function must handle:
      - Empty list check.
      - Single-node list deletion (resets head to NULL).
      - Head node deletion (pos == 1).
      - Intermediate and tail node deletion.
      - Out-of-bounds position validation.
    Key Algorithmic Concepts:
      - Advances directly to the target node curr at position pos.
      - Bridges the target's neighbors: curr->prev->next = curr->next and
        curr->next->prev = curr->prev with appropriate NULL checks.
    Why It's Unique:
      In SLL positional deletion, traversal must stop at the predecessor node
      (pos - 1) because backward navigation is impossible. In DLL, traversal
      advances directly to the target node at position pos, because the node
      itself provides immediate access to both predecessor and successor.

--------------------------------------------------------------------------------

[4] ReverseDLL.c (Question 48)
    Category: In-Place Pointer Swapping Reversal
    Problem Statement:
      Reverse a doubly linked list completely in-place in O(N) time and O(1)
      auxiliary space such that the original tail becomes the new head.
    Key Algorithmic Concepts:
      - Symmetrical node inversion: for every node, swap its prev and next
        pointers using a temporary swap pointer.
      - Traversal direction inversion: after swapping pointers in curr, the
        next logical node in the original sequence is reached via curr->prev.
      - Head rebinding: updates *head to the last non-null node.
    Why It's Unique:
      Reversing an SLL requires a 3-pointer sliding window (prev, curr, next).
      In a DLL, reversal reduces to locally swapping the prev and next pointers
      within each node, demonstrating the algebraic symmetry of bidirectional links.

--------------------------------------------------------------------------------

[5] FindPrevNextDLL.c (Question 50)
    Category: Symmetric O(1) Relative Lookups
    Problem Statement:
      Implement two lookup queries for a doubly linked list:
      1. findPrev(head, x): Return a pointer to the immediate predecessor of
         the first node containing value x (NULL if x is head or not found).
      2. findNext(head, x): Return a pointer to the immediate successor of
         the first node containing value x (NULL if x is tail or not found).
    Key Algorithmic Concepts:
      - Linear search to locate the target node pointer.
      - Instantaneous predecessor (target->prev) and successor (target->next)
        access in O(1) time without secondary traversal.
    Why It's Unique:
      Demonstrates the major operational advantage of DLL over SLL. Finding
      the predecessor of an element in an SLL requires keeping a trailing
      pointer during search or re-traversing from head (O(N)). In DLL, predecessor
      lookup is an instantaneous O(1) pointer dereference.

[6] BrowserNavigationDLL.c (Question 51)
    Category: Destructive Timeline State Machine
    Problem Statement:
      Design a browser history navigation system using a DLL supporting:
      1. visit(url): Visit a new URL from the current page. Visiting a new page
         must permanently discard and free all forward browsing history ahead
         of the current page.
      2. back(): Navigate back one page (current = current->prev).
      3. forward(): Navigate forward one page (current = current->next).
      4. displayCurrentPage(): Print the active page URL.
    Key Algorithmic Concepts:
      - Maintains a single state cursor pointer (current).
      - Sub-chain clearing: traverses and frees all forward nodes starting from
        current->next before attaching the new page.
    Why It's Unique:
      Models LeetCode 1472 ("Design Browser History"). It treats the DLL as a
      dynamic timeline where moving backward preserves history, but navigating
      to a new state destructively truncates the forward timeline.

[7] LRUCacheSimulation.c (Question 54)
    Category: Hybrid Architecture (DLL + Hash Map for O(1) Operations)
    Problem Statement:
      Design and implement a Least Recently Used (LRU) Cache of fixed capacity K
      supporting two operations in O(1) average time:
      1. get(key): Return value if present (HIT) and promote node to head (MRU).
         Return -1 on MISS.
      2. put(key, value): Insert/update key-value pair and promote to head (MRU).
         If capacity K is exceeded, evict the LRU node at the tail of the DLL.
    Key Algorithmic Concepts:
      - Hybrid design: direct lookup table (hash map) maps key -> CacheNode*,
        while the DLL maintains temporal access order.
      - DLL provides O(1) arbitrary node detachment (detachNode), O(1) head
        insertion (addToHead), and O(1) tail eviction.
    Why It's Unique:
      The premier real-world system design application of Doubly Linked Lists
      (used in OS virtual memory, Redis, database page caches). Proves why SLL
      is insufficient: unlinking an arbitrary node in SLL requires O(N) search
      for its predecessor, whereas DLL enables true O(1) unlinking.

[8] PalindromeCheckDLL.c (Question 55)
    Category: Inward Two-Pointer Convergence (O(1) Auxiliary Space)
    Problem Statement:
      Given a doubly linked list with head and tail pointers, determine whether
      the node sequence forms a palindrome. The algorithm must run in O(N) time,
      use O(1) auxiliary space, and must NOT modify or reverse list pointers.
    Key Algorithmic Concepts:
      - Dual-ended pointers: left = head, right = tail.
      - Inward progression: left = left->next, right = right->prev.
      - Meeting / crossing conditions: terminates when left == right (odd length)
        or left->prev == right (even length).
    Why It's Unique:
      In an SLL, palindrome verification requires midpoint splitting (Tortoise &
      Hare), reversing the second half, comparing, and re-reversing. In a DLL,
      bidirectional pointers allow direct, non-destructive inward convergence
      identical to two-pointer string palindrome checks.

--------------------------------------------------------------------------------

[9] SortedInsertDLL.c (Question 56)
    Category: Dual-Link Ordered Invariant Maintenance
    Problem Statement:
      Given a doubly linked list maintained in ascending sorted order, insert a
      new node with value val into its correct position while preserving sorted
      order and bidirectional link consistency.
    Key Algorithmic Concepts:
      - Empty list case (newNode becomes sole head).
      - Head insertion case (val <= (*head)->data updates (*head)->prev).
      - Intermediate search predicate: curr->next == NULL || curr->next->data >= val.
      - Dual-link splicing with successor NULL validation.
    Why It's Unique:
      The fundamental building block for Linked List Insertion Sort. Requires
      managing 4-way pointer bindings based on data value comparison predicates
      rather than positional index counts.

--------------------------------------------------------------------------------

[10] DeleteGivenNodeDLL.c (Question 57)
    Category: Direct O(1) Node Pointer Deletion Without Traversal
    Problem Statement:
      Given ONLY a direct pointer del to a node in a doubly linked list (along
      with struct Node** head), delete node del and free its memory in true O(1)
      time complexity without traversing the list.
    Key Algorithmic Concepts:
      - Head deletion: if (*head == del) *head = del->next.
      - Successor rewiring: if (del->next != NULL) del->next->prev = del->prev.
      - Predecessor rewiring: if (del->prev != NULL) del->prev->next = del->next.
      - Free del.
    Why It's Unique:
      Highlights the definitive architectural difference between SLL and DLL.
      In an SLL, deleting a node given only its pointer is an infamous hack
      (copying data from del->next), which fails on the tail node. In a DLL,
      true O(1) deletion of ANY node (including the tail) is natively supported.

[11] CircularDoublyLinkedList.c (Question 58)
    Category: Circular Doubly Linked Ring ADT & Tail-Head Direct Access
    Problem Statement:
      Design and implement a Circular Doubly Linked List (CDLL) where
      tail->next == head and head->prev == tail. Implement:
      1. isEmpty(head) and isLastNode(head, node).
      2. insertAtHead: O(1) head insertion.
      3. insertAtTail: O(1) tail insertion using ONLY the head pointer.
      4. insertAtPosition: 1-based index positional insertion.
      5. Bidirectional cyclic traversal.
    Key Algorithmic Concepts:
      - Ring invariant: no node has prev == NULL or next == NULL.
      - O(1) tail access via head: tail is always immediately (*head)->prev.
      - Loop termination: replaces NULL checks with cyclic equality (curr == head).
    Why It's Unique:
      Culmination of linked list topologies. Linking head and tail bidirectionally
      eliminates the need to maintain an independent tail pointer—the head
      pointer alone provides instantaneous O(1) access to both ends of the list.
